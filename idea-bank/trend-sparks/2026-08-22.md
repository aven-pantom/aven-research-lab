# Trend Sparks — 2026-08-22

## Source scan

- arXiv API scan for tool-use agents, software architecture, model routing, agentic search, task-model induction, AI video editing, group/identity image generation, video virtual try-on, UAM/drone coordination, and synthetic drone-weather datasets.
- GitHub API repository scans for MCP servers, browser agents, AI video editors, vibe-coding/mobile coding apps, local-first AI, virtual try-on, drone planners, and creative/content agents. One later broad GitHub search hit API rate limits and was not used as evidence.
- Internal corpus scan across Context Budgets, State Barometers, Task Models, Package Quarantine, Fit Ledgers, Reference Contracts, Weather/Radio/Acoustic drone cards, Imaginary Rooms, and Personal Software Workshops.

## Selection logic

Picked opportunities where a visible technical/product signal points to a small behavior loop: review, rehearse, inspect, share, correct, or reuse. Preference went to Max-aligned surfaces: agent infrastructure, creative tools, fashion/taste engines, mobile/vibe-coding workflows, and simulator-only aviation interfaces.

## Anti-slop filter

Rejected generic AI wrappers, “compress everything” tools without evidence contracts, cloned video editors, basic outfit generators, operational drone planners that imply safety/clearance, and monetization-only social features with no retention loop.

## Strongest three to watch

1. **Tool Output Diet Card** — strongest because MCP/tool growth makes context admissibility a near-term runtime problem.
2. **AI Video Workbench Receipt** — strong creative wedge because local/AI video editors are appearing as concrete product surfaces, not just model demos.
3. **Phone Coding Cockpit** — strong consumer/developer wedge because mobile vibe-coding control surfaces are now visible and naturally need receipts, status, and handoff.

## Sparks

### 1. Tool Output Diet Card

- **Trend signal:** Agent products are adding tools, MCP servers, browser drivers, codebase indexes, and context compressors; tool output is becoming a product surface.
- **Existing proof:** **Verified:** GitHub API metadata showed `headroomlabs-ai/headroom` positioning around compressing tool outputs/logs/files/RAG chunks; `MidTool` uses real tool APIs, MCP skills, and workflows as tool-use training material.
- **Gap:** Users see raw dumps or compressed summaries, but not what evidence was preserved, dropped, redacted, quarantined, or safe to act on.
- **Smallest prototype:** A Markdown/JSON card attached to one tool result: source, authority, raw pointer, what it proves, what it cannot prove, transformations, staleness, mutation eligibility, and required recheck.
- **Why it could spread:** Agent builders can attach cards to bug reports and PRs: “this tool result was not admissible for that action.”
- **Risk / why it may be fake:** May become compliance theater if it repeats summaries instead of changing action eligibility.
- **Fit for Max:** Direct fit for Hermes/Aven, context budgets, package quarantine, MCP receipts, and local-first agents.
- **Evidence label:** **Supported**.

### 2. AI Video Workbench Receipt

- **Trend signal:** AI video editors are becoming local/productized tools instead of only hosted generation demos.
- **Existing proof:** **Verified:** GitHub API search for `ai video editor created:>2025-01-01` returned `palmier-io/palmier-pro`, `OpenChatCut`, and `Gausian_native_editor`; OpenChatCut describes a local-first conversational AI video editor with timeline, Agent Skills, MCP, and Remotion rendering.
- **Gap:** Editors can generate/modify clips, but users lack a compact receipt for sources, prompts, timeline edits, agent actions, preserved references, and export confidence.
- **Smallest prototype:** A workbench receipt for a 15-second edit: inputs, timeline changes, model/tool calls, rejected branches, preserved invariants, and next edit prompt.
- **Why it could spread:** Creators can share receipts with collaborators/clients as “how this edit was made and what can still be changed.”
- **Risk / why it may be fake:** Creators may prefer speed over provenance until collaboration breaks.
- **Fit for Max:** Strong Pantom/Orior creative-tool and provenance lane.
- **Evidence label:** **Supported**.

### 3. Phone Coding Cockpit

- **Trend signal:** Vibe-coding is moving onto mobile control surfaces for Codex/Claude Code/OpenCode-style agents.
- **Existing proof:** **Verified:** GitHub API search for `vibe coding app created:>2025-01-01` returned `tiann/hapi`, described as an app for Codex / Claude Code / Pi / OpenCode / Kimi Code / Grok Build, and `automazeio/vibeproxy`, a macOS menu-bar app for AI coding-tool subscriptions.
- **Gap:** Mobile coding control needs more than chat: task phase, branch, dirty files, tests, next risky mutation, hold/approve, and continuation handoff.
- **Smallest prototype:** A read-only phone cockpit for one local agent run with status cards and approval gates; no code editing from phone in v1.
- **Why it could spread:** People want to supervise coding agents while away from the desk without trusting blind background autonomy.
- **Risk / why it may be fake:** Could become another thin remote terminal if it lacks real state receipts.
- **Fit for Max:** Strong fit for Hermes, Aven continuity, agent peripheral vision, and local-first workbenches.
- **Evidence label:** **Supported**.

### 4. MCP Tool Path Inspector

- **Trend signal:** MCP server ecosystems are visibly expanding across GitHub, browser, DevTools, Playwright, codebase memory, and specialized tool servers.
- **Existing proof:** **Verified:** GitHub API metadata showed active high-star repositories including `microsoft/playwright-mcp`, `github/github-mcp-server`, `ChromeDevTools/chrome-devtools-mcp`, and `DeusData/codebase-memory-mcp`.
- **Gap:** Agent users know a tool was used, but not why it was chosen, what authority it carried, what it read, what it wrote, or what residue remains.
- **Smallest prototype:** A local inspector card for one task showing selected tools, rejected tools, permissions, reads/writes, residue, and safer alternative path.
- **Why it could spread:** Developers can paste tool-path cards into issue reports and reviews.
- **Risk / why it may be fake:** Runtime telemetry formats may fragment.
- **Fit for Max:** Directly aligns with capability receipts, package quarantine, credential leases, and action maps.
- **Evidence label:** **Supported**.

### 5. Group Identity Binding Board

- **Trend signal:** Image generation is pushing from single-subject identity preservation toward many specified people in one scene.
- **Existing proof:** **Verified:** `WithEveryone: Unified Planning and Identity Grounding for Group Image Generation` targets retaining identities while binding each reference to a distinct person and location.
- **Gap:** Creators need to review which reference became which person, where identity drift happened, and what should be locked before regeneration.
- **Smallest prototype:** A board with reference slots, person/location bindings, protected traits, drift notes, and revision instructions.
- **Why it could spread:** “Who did the model turn everyone into?” is visually shareable and useful for events, brands, crews, and family/group content.
- **Risk / why it may be fake:** Identity tools raise consent/privacy issues and can become creepy if not scoped to user-owned references.
- **Fit for Max:** Fits reference contracts, Orior/Pantom creative workflows, and taste-aware review tools.
- **Evidence label:** **Supported**.

### 6. Try-On Motion Skeptic

- **Trend signal:** Video virtual try-on research and repos are becoming concrete, but rendered motion does not equal reliable physical fit.
- **Existing proof:** **Verified:** Prior arXiv scan found `InstructVVT` and `UniVVT`; GitHub API search for `virtual try on created:>2025-01-01` returned `vivoCameraResearch/Magic-TryOn`, `nxnai/Voost`, and `fashn-AI/fashn-vton-1.5`.
- **Gap:** Shoppers see a plausible clip without labels for sleeve behavior, occlusion, garment identity, motion artifacts, and buy-risk zones.
- **Smallest prototype:** A human-in-the-loop receipt overlay for a try-on clip with preserved/unknown/likely-fake motion zones and “do not buy from this alone” warning.
- **Why it could spread:** It turns try-on skepticism into a useful share/review artifact rather than a hidden doubt.
- **Risk / why it may be fake:** Without ground-truth fit data, the first version judges visual reliability, not actual comfort.
- **Fit for Max:** Strong fashion/taste-engine lane with trust and restraint.
- **Evidence label:** **Supported**.

### 7. Local Memory Constitution

- **Trend signal:** Local-first AI systems are marketing persistent personal memory and offline ownership.
- **Existing proof:** **Verified:** GitHub API query returned `tinyhumansai/openhuman` as a local-first memory/orchestrator product and `janhq/jan` as an offline ChatGPT alternative updated on 2026-08-22.
- **Gap:** Local memory products need a user-readable constitution: what may be remembered, promoted, forgotten, corrected, exported, or forbidden.
- **Smallest prototype:** A local Markdown constitution with evidence receipts for each rule and an expiry/review queue.
- **Why it could spread:** People trust “show me what my AI is allowed to remember and why” more than generic memory toggles.
- **Risk / why it may be fake:** Users may not maintain it unless corrections automatically propose updates.
- **Fit for Max:** Strong fit for behavioral canon and resident microbrains.
- **Evidence label:** **Supported**.

### 8. Creator Agent Crew Receipt

- **Trend signal:** Creative/content stacks are packaging multiple agents around scripts, reels, publishing, and creative coding.
- **Existing proof:** **Verified:** GitHub API search for `creative coding agent created:>2025-01-01` returned `timkoda/koda-stack`, described as 10 creative agents for content pipeline automation, and `sxp-studio/subjective-zero`, described as an agentic editor for creative coding and realtime visual effects.
- **Gap:** Multi-agent creative work lacks a visible division of labor, decision log, and handoff receipt.
- **Smallest prototype:** A crew receipt for one reel/design artifact: agent roles, inputs, decisions, conflicts, human approvals, exports, and reusable lessons.
- **Why it could spread:** Creators can turn the behind-the-scenes agent crew into both trust artifact and content.
- **Risk / why it may be fake:** Could become performative if it does not improve revision speed.
- **Fit for Max:** Strong creator funnel/Pantom lane.
- **Evidence label:** **Supported**.

### 9. Drone Route Evidence Diff

- **Trend signal:** Public drone planning repos exist, while Vibe research keeps finding that route evidence should be separated from authorization.
- **Existing proof:** **Verified:** GitHub API search for `drone planner created:>2025-01-01` returned `fcsonline/droneroute`, an open-source DJI waypoint mission planner; prior arXiv scan found UAM merge coordination and synthetic drone-weather dataset work.
- **Gap:** Planning interfaces show paths, but not a non-authorizing evidence diff: what changed in weather, radio, noise, airspace, route assumptions, and freshness since last review.
- **Smallest prototype:** Simulator-only route diff cards comparing two fictional plan states with explicit “not clearance / not operational guidance” labels.
- **Why it could spread:** Useful for design reviews and autonomy trust conversations without touching real operations.
- **Risk / why it may be fake:** Dangerous if it implies live operational safety or route approval.
- **Fit for Max:** Good Notrex/N1 Scout-adjacent interface research if kept simulator-only.
- **Evidence label:** **Supported**.

### 10. Agentic Search Evidence Hop Viewer

- **Trend signal:** Agentic search evaluation is moving toward decomposed, verifiable evidence chains instead of opaque browsing success.
- **Existing proof:** **Verified:** `Projecting BrowseComp-Plus onto ClimbMix` decomposes questions into atomic reasoning hops and keeps items only when automatic verification, an independent agent, and human review confirm support.
- **Gap:** Normal research assistants return source lists, but not hop-by-hop evidence dependency and weak-link visibility.
- **Smallest prototype:** A viewer that turns one research answer into atomic claims, evidence hops, verification status, weak links, and raw source pointers.
- **Why it could spread:** Researchers, founders, and agents can share “where this answer actually rests” instead of dumping links.
- **Risk / why it may be fake:** Hop decomposition may be too slow for casual search.
- **Fit for Max:** Strong Orior/source-first dossier and Vibe Research portal fit.
- **Evidence label:** **Supported**.
