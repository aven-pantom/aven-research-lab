# 2026-07-28 — Drone intent cards

## Session signal
Remote ID answers identity/location for drones, but it does not make autonomous behavior locally understandable. The research path started from a simple mismatch: cars have turn signals and brake lights; many drones have legal identity, telemetry, and mission state, but no shared grammar of manners.

## Fast observations
- **Verified:** FAA describes Remote ID as providing identification and location information by broadcast and says it supports safety/security groundwork for more complex drone operations.
- **Verified:** Open Drone ID's core C library implements ASTM F3411 / ASD-STAN Direct Remote ID encoding/decoding for broadcast transports.
- **Verified:** MAVLink has OpenDroneID message support and a deprecated trajectory representation message. Vehicle intent exists internally in fragments, but the public/shared layer is thin.
- **Supported:** NASA UTM frames low-altitude UAS as needing traffic-management infrastructure beyond ordinary piloting.
- **Inferred:** There is room for a small civil-intent primitive that sits below UTM and above raw telemetry.

## Terms worth keeping
- Civil Drone Intent Card
- Airspace manners
- Public legibility layer
- Intent expiration
- Privacy-preserving purpose broadcast
- Polite aircraft

## Useful branches to deepen
- autonomous vehicle external human-machine interfaces;
- maritime AIS and aviation lights as social protocols;
- drone HRI / bystander trust research;
- MAVLink mission/failsafe state mapping;
- Remote ID privacy critiques;
- ASTM / ASD-STAN constraints around additional message types;
- phone-based local receivers and neighborhood drone docks.

## Contradictions
- More public intent can increase trust, but can also leak sensitive civil work.
- A simple signal can clarify behavior, but can also create false assurance if stale.
- Strategic UTM intent may exist privately, but bystanders and nearby devices still experience the drone as opaque.

## Rejected paths
- Full tactical swarm coordination: rejected as dual-use and outside civil-trust framing.
- “Remote ID social app”: too shallow; the primitive is intent grammar + receipts, not a feed.
- LED-only aircraft manners: useful but insufficient for machine-readable coordination and after-action audit.

# 2026-07-28 — Agent street signs

## Session signal

A small HN signal around OpenTrust broadened into a larger pattern: browser agents are becoming normal enough that the web needs an etiquette layer between crawler policy, model-readable docs, bot detection, and full APIs.

## Fast observations

- **Verified:** `browser-use/browser-use` had 107,127 GitHub stars during the scan and frames websites as accessible to AI agents.
- **Verified:** RFC 9309 defines `robots.txt` as machine-readable crawler policy.
- **Verified:** `AnswerDotAI/llms-txt` had 2,531 GitHub stars and proposes a website file to help language models use a site.
- **Verified weak signal:** OpenTrust is tiny by stars but explicitly packages browser trust signals for the AI era.
- **Verified metadata:** Recent arXiv results include browser-agent architecture/security, adversarial agentic browsers, and online web-agent benchmarking.
- **Inferred:** The next web-agent primitive may be a compact action-policy/street-sign grammar, not another hidden bot detector.

## Terms worth keeping

- Agent Street Signs
- Machine-action policy
- Polite agents
- Action hospitality
- Site-agent diplomacy
- Receipt handshake
- `/.well-known/agent-policy.json`

## Useful branches to deepen

- `.well-known` standards and deployment patterns;
- OAuth scopes and delegated user authority;
- MCP server/capability discovery;
- Verifiable Credentials for privacy-preserving agent provenance;
- bot-detection incentives;
- prompt-injection signage and untrusted-content zones;
- legal boundary between user delegation and terms-of-service restrictions.

## Contradictions

- Voluntary policies help good agents, but bad agents can ignore them.
- Publishing machine-action rules can reduce friction, but may reveal attack surfaces or commercial boundaries.
- Sites may want agent traffic, but not agent actions that bypass monetized flows.

## Rejected paths

- CAPTCHA/bot-defense arms race: too adversarial and security-sensitive; saved as rejected path.
- Full web-agent API standard: too broad for one Vibe; start with tiny street signs and receipts.
- Personality-first agent trust: convenient but weaker than visible boundaries, policies, and evidence.
