# Field Notes — Memory Compost

## Date

2026-09-02

## Signal

Agent memory is becoming infrastructure, but the visible language still leans toward persistence and retrieval. The strange gap is memory decay: not deleting everything, not remembering everything, but transforming stale memories into lower-authority material.

## Observations

- `mem0ai/mem0`, `getzep/graphiti`, and `letta-ai/letta` all position memory/state as core agent infrastructure.
- arXiv `2504.19413` and `2501.13956` both emphasize long-term, cross-session memory and graph/temporal structure.
- Coding agents and browser-agent infrastructure are active enough that bad memory will increasingly mutate external state.
- Prior lab Vibes already imply a memory hierarchy: media ledger evidence, behavioral canon, taste constraints, context budgets, and state barometers are all different authority classes.

## Useful phrase

Memory should decay into usable soil, not remain as stale facts.

## Questions

- What memory states belong in the first fixture: fresh, aging, contradicted, context-only, composted, canon candidate, deleted residue?
- Can an agent cite a composted memory as style pressure while refusing to use it as factual authority?
- Do corrections become the richest compost because they compress a failed expectation plus the desired rule?

## Rejected fast paths

- Building a generic memory viewer.
- Treating memory decay as only privacy deletion.
- Assuming graph memory automatically solves authority and expiry.
