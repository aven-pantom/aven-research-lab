## Selection logic

Picked app opportunities where a visible behavior already exists, but the user-facing primitive is still unresolved: verifying agent work, making personal taste portable, reducing creative-tool friction, giving local agents peripheral controls, or making drone/autonomy behavior legible.

## Anti-slop filter

Rejected generic wrappers where the loop was only “add AI chat to X.” Each Spark below needs a repeat behavior: watching agent state, capturing work traces, saving taste events, comparing edits, sharing artifacts, or verifying autonomous action.

## 1. Transition Card Recorder

- **Trend signal:** Desktop-Delta Bench appeared on arXiv 2026-07-28, and HN/source signals show active movement in browser/desktop agents.
- **Existing proof:** **Verified:** arXiv abstract reports a benchmark for GUI transition understanding; GitHub API shows heavy attention around browser-use and MCP servers.
- **Gap:** Agent logs usually show actions or chat, not expected vs observed state deltas.
- **Smallest prototype:** Playwright wrapper that records before/after screenshot + DOM/a11y diff + expected delta + pass/fail/unknown judgment for one task.
- **Why it could spread:** Every builder of browser agents needs a way to show what the agent actually changed.
- **Risk / why it may be fake:** Teams may prefer internal observability or final-state checks over a user-visible trace layer.
- **Fit for Max:** Directly aligned with Aven/Hermes, agent tools, local-first evidence, and interface primitives.
- **Evidence label:** **Supported**

## 2. Parallel Agent Control Tower

- **Trend signal:** HN surfaced MindFlock on 2026-07-29: parallel AI coding agents, each in its own Git worktree.
- **Existing proof:** **Verified:** HN listing points to a public GitHub repo; multiple coding-agent tools are competing around parallel execution.
- **Gap:** Worktree isolation is not enough; users need a calm surface for status, conflicts, risk, and merge readiness.
- **Smallest prototype:** Local web/menubar app that watches N git worktrees and shows agent phase, changed files, failing tests, merge risk, and “pause/kill/merge draft” controls.
- **Why it could spread:** The moment users run more than one coding agent, chat becomes a bad control surface.
- **Risk / why it may be fake:** Existing IDEs or agent CLIs may absorb this as a panel.
- **Fit for Max:** Strong: agent operations, clean cockpit UI, Pantom-adjacent tooling.
- **Evidence label:** **Supported**

- **Risk / why it may be fake:** Privacy anxiety and noisy captures may make the data unusable.
- **Fit for Max:** Strong: creator funnels, local-first agents, operational tooling.
