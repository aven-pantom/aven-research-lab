# Rejected Path — Generic Multi-Agent Project Manager

## Why it initially seemed promising

If multiple coding agents work at once, a dashboard assigning tasks, showing statuses, and chatting with agents sounds useful.

## What weakened it

The idea collapses into familiar project-management software with agent labels. It does not address the more specific failure: agents mutate overlapping repository surfaces with stale or partial knowledge.

## Failed assumption

The coordination problem is not primarily “who is doing what?” It is “which surfaces are currently occupied, which assumptions are stale, and which mutations require revalidation before action?”

## Useful remnants

- Actor identity still matters.
- Task status still matters.
- The dashboard may become useful later as a view over Workspace Cartography Cards.

## Future trigger for reconsideration

Revisit a broader project-manager layer only after a card fixture proves that surface claims, stale-state warnings, and overlap detection materially improve agent work.
