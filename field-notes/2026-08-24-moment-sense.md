# Field Notes — 2026-08-24 — Moment Sense

## Raw observations

- arXiv `2608.21360` (*OmniAssistBench*) was the strongest signal: the abstract explicitly names failures around visual prompts, historical context, and delaying response until the target event.
- GitHub API scan showed strong, current movement around live agent substrates: `livekit/agents` for real-time voice/video agents, `screenpipe/screenpipe` for local continuous computer history, `browser-use/browser-use`, `microsoft/playwright-mcp`, and `ChromeDevTools/chrome-devtools-mcp` for browser/computer-use surfaces.
- HN date scan showed weak but current public signals around agent latency, browser agents, MCP tools, AI video tools, and multi-worktree agent coordination.
- The repeated issue is not “more context.” It is timing: when should an assistant wait, interrupt, guide, suppress, or debrief?

## Questions

- Can moment classification be local and cheap enough to run as a resident microbrain?
- How much of intervention timing can be inferred from UI/video state versus learned from a person's corrections?
- What receipt proves an assistant waited appropriately without retaining invasive raw recordings?
- Is the first wedge creative/live critique, phone notifications, browser agents, tutorials, or coding-agent supervision?

## Failed searches / weak paths

- Generic “AI assistant app” scans were too product-shaped and not primitive-level.
- Broad arXiv searches for GUI/browser agents returned noisy results unless anchored to the exact OmniAssistBench signal.
- Pure agent-latency framing was too infrastructural; the sharper issue is temporal governance, not milliseconds alone.

## Promoted signal

Assistance needs Moment Sense: a phase-aware intervention contract that decides when help should arrive before deciding what it should say.
