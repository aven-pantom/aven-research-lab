# Trend Sparks — 2026-07-28

Exactly 10 current, evidence-backed app opportunities from visible product/social/developer behavior. These are Trend Sparks, not generic ideas.

## 1. Agent Run Receipts
- **Trend signal:** Claude Code, GitHub Copilot coding agent, browser-use agents, and MCP-style tool connections are pushing agents into real repositories and workflows.
- **Existing proof:** **Verified:** Anthropic publishes Claude Code docs; GitHub publishes Copilot coding-agent docs; Model Context Protocol has public repositories and docs; recent lab Vibes already found repeated demand for agent flight recorders/peripheral vision.
- **Gap:** People can see final diffs or chats, but not a clean receipt of what the agent observed, changed, skipped, and why.
- **Smallest prototype:** Local CLI/browser wrapper that turns one agent run into a shareable Markdown/HTML receipt: objective, scope, files touched, commands run, approvals, uncertainty, raw trace links.
- **Why it could spread:** Receipts travel naturally in PRs, client updates, Discord build logs, and “watch my agent work” content.
- **Risk / why it may be fake:** Agent platforms may build this natively; users may tolerate opaque work if output is good enough.
- **Fit for Max:** Very high: agents, local-first tools, design-quality developer UX, Pantom/Orior ops.
- **Evidence label:** Supported.

## 2. Phone Cockpit for Long Agent Tasks
- **Trend signal:** More coding/research agents run for minutes or hours while users leave the desktop.
- **Existing proof:** **Verified:** Claude Code and Copilot coding agent are documented as real developer workflows; prior lab research identified peripheral-vision gaps in computer-use agents.
- **Gap:** Existing interfaces are desktop/chat-centric. Users need lightweight supervision: phase, next risky action, blockers, approve/hold, replay link.
- **Smallest prototype:** A local web app with push-style polling for one repo task: status bands, confidence, last meaningful event, “pause before write,” and final receipt.
- **Why it could spread:** Screenshots of a phone supervising an agent are legible and aspirational; it makes autonomy feel controllable.
- **Risk / why it may be fake:** Notification fatigue; platforms could ship first-party mobile monitoring.
- **Fit for Max:** High: strong interface primitive for autonomous work.
- **Evidence label:** Supported.

## 3. Closet Drop Radar
- **Trend signal:** Resale, outfit planning, and fashion taste engines keep converging around personal wardrobes and drop culture.
- **Existing proof:** **Verified:** Major resale and fashion platforms expose persistent behaviors around saved searches, listings, fits, and drops; the lab's wardrobe-memory Vibe already mapped the gap between virtual try-on and real wear history.
- **Gap:** Users track scattered alerts across resale sites, brand newsletters, TikTok, screenshots, and closet gaps without a personal style memory.
- **Smallest prototype:** Manual upload of closet anchors + saved target items; daily digest of “drops that complete outfits you actually wear,” with source links and reject reasons.
- **Why it could spread:** Shareable “found the missing piece” cards and creator closet hunts.
- **Risk / why it may be fake:** Scraping/search quality is hard; affiliate incentives can corrupt taste.
- **Fit for Max:** High: fashion/taste engine + content funnel.
- **Evidence label:** Inferred from supported platform behavior.

## 4. Reference Camera for Designers
- **Trend signal:** Designers and creators collect screenshots, photos, palettes, UI details, textures, and typography constantly, but camera rolls are poor reference systems.
- **Existing proof:** **Verified:** Pinterest developer docs support content workflows; TikTok content APIs exist; prior lab camera/color Vibes identified camera-native creative capture as a recurring frontier.
- **Gap:** Saving inspiration is easy; extracting roles, palette function, layout rhythm, and reusable tokens is still manual.
- **Smallest prototype:** Mobile/web capture inbox that turns a photo/screenshot into a reference card: palette roles, typography notes, layout density, material tags, and “why saved.”
- **Why it could spread:** Shareable reference cards are useful in design Twitter, moodboards, client decks, and creator behind-the-scenes.
- **Risk / why it may be fake:** Could become another AI moodboard wrapper unless it preserves designer judgment and source context.
- **Fit for Max:** Very high: design taste, Orior/Pantom, creative tools.
- **Evidence label:** Supported.

## 5. Micro-Portal for Markdown Worlds
- **Trend signal:** Personal/public knowledge repositories, docs sites, and agent-maintained Markdown corpora are becoming common, but most portals require framework overhead.
- **Existing proof:** **Verified:** This lab already uses a static portal manifest over Markdown; GitHub Pages and static hosting patterns are established.
- **Gap:** Nontechnical creators want a beautiful lens over a folder without migrating into Notion, a CMS, or a database.
- **Smallest prototype:** Drop-in `portal/` that indexes Markdown into search, categories, outlines, raw links, dark/light mode, and shareable URLs.
- **Why it could spread:** Every repo, course, research lab, and creator archive can publish a “world” with one command.
- **Risk / why it may be fake:** Static site generators already exist; wedge must be zero-migration + aesthetic/tasteful.
- **Fit for Max:** High: local-first, research lab, Orior documents, Wormkey-style links.
- **Evidence label:** Verified for local proof; supported for broader static-doc behavior.

## 6. Drone Intent Receiver
- **Trend signal:** Remote ID, UTM, delivery/inspection drones, and local autonomy create a public-legibility problem around small aircraft.
- **Existing proof:** **Verified:** FAA Remote ID guidance exists; Open Drone ID implements Remote ID messages; MAVLink carries OpenDroneID and aircraft state primitives.
- **Gap:** People nearby can identify a drone but cannot easily tell whether it is landing, yielding, inspecting, returning home, or failing.
- **Smallest prototype:** Simulator-first web receiver that displays civil intent cards from synthetic MAVLink/Remote-ID-like events; no flight hardware.
- **Why it could spread:** “Turn signals for drones” is a clear demo and a strong aviation-interface story.
- **Risk / why it may be fake:** Regulation and privacy may block public purpose display; actual broadcasts may not expose enough signal.
- **Fit for Max:** Very high: drones, aviation, interface primitives.
- **Evidence label:** Supported.

## 7. Creator Funnel Flight Recorder
- **Trend signal:** Creators increasingly run content through repeatable funnels: capture, clip, caption, remix, schedule, cross-post, analyze.
- **Existing proof:** **Verified:** TikTok and Pinterest maintain content posting/content APIs; creator tooling visibly centers repurposing and scheduling workflows.
- **Gap:** Tools manage posts, but rarely show which creative decisions created lift or dead ends across the whole funnel.
- **Smallest prototype:** A local funnel log where each content asset has source, edits, captions, hooks tried, channels, publish status, and manual outcome notes.
- **Why it could spread:** Shareable teardown cards: “this reel became these five assets.”
- **Risk / why it may be fake:** Without platform analytics access, outcome data may be manual and incomplete.
- **Fit for Max:** High: content engine, Pantom/Orior, agent-maintained operations.
- **Evidence label:** Supported.

## 8. Local Taste Model for Shopping Screenshots
- **Trend signal:** People shop through screenshots, wishlists, social saves, resale searches, and DMs rather than one clean catalog.
- **Existing proof:** **Supported:** Fashion/resale/social platforms all encourage save/share behavior; prior wardrobe-memory research showed personal fit history is the missing context.
- **Gap:** Current recommendation systems know platform behavior, not cross-platform personal taste and actual wardrobe use.
- **Smallest prototype:** Browser/mobile inbox for shopping screenshots; cluster by silhouette, color, brand world, price, closet fit, and “will I actually wear it?”
- **Why it could spread:** Users can share taste maps and “do not let me buy this again” cards.
- **Risk / why it may be fake:** Manual input friction; style quality must feel tasteful, not generic.
- **Fit for Max:** High: fashion, taste engines, calm consumer utility.
- **Evidence label:** Inferred.

## 9. Personal API Desk
- **Trend signal:** Stripe Terminal, MCP servers, Cloudflare Agents, and app intents all point toward everyday tools exposing programmable surfaces.
- **Existing proof:** **Verified:** Stripe Terminal and Cloudflare Agents docs exist; MCP repositories exist; Apple documents App Intents under developer documentation even though the initially probed URL returned 404.
- **Gap:** Non-engineers cannot see what their apps can safely do for agents or compose them into bounded workflows.
- **Smallest prototype:** Local catalog of connected app actions with plain-language verbs, required scopes, dry-run mode, and receipts.
- **Why it could spread:** “What can my computer do for me?” is a natural onboarding artifact for personal agents.
- **Risk / why it may be fake:** Permissions are fragmented and OAuth setup is painful.
- **Fit for Max:** Very high: local-first agents, bounded rooms, personal software workshops.
- **Evidence label:** Supported with one noted source-access caveat.

## 10. Weird Utility: Receipt-to-Object Memory
- **Trend signal:** People buy, return, resell, repair, and insure objects across fragmented inboxes, wallets, resale apps, and screenshots.
- **Existing proof:** **Supported:** Email receipts, wallet passes, resale listings, and product manuals are all persistent but disconnected artifacts; local-first personal software is a repeated lab direction.
- **Gap:** There is no calm personal object ledger that remembers ownership, warranty, resale value, repair history, manuals, and why the object was bought.
- **Smallest prototype:** Email/PDF/manual upload for 20 objects; object cards with purchase proof, warranty dates, resale notes, repair log, and “keep/sell/replace” status.
- **Why it could spread:** Satisfying before/after household inventory videos; useful for moving, insurance, resale, and style/content setups.
- **Risk / why it may be fake:** Existing finance/inventory apps may be “good enough”; automatic parsing quality matters.
- **Fit for Max:** Medium-high: weird consumer utility with local-first memory and elegant object interface.
- **Evidence label:** Inferred.
