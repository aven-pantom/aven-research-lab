# Field Notes — 2026-08-23 — Taste Compilers

## Raw observations

- arXiv fashion recommendation search showed a useful arc: surveys and compatibility models → LLM/sequential recommendation → diffusion/generative outfit recommendation → negative-feedback styling.
- Product surfaces split the evidence: LTK/Pinterest hold consumer taste behavior; Immich/camera rolls hold personal visual memory; ComfyUI/Figma/Runway/Suno/CapCut hold creative generation workflows.
- The repeated missing object is not “more recommendations.” It is a portable rule layer that says what must remain true.
- Prior lab primitives are converging: Negative Taste Events, Fit Ledger Cards, Reference Contracts, Portable Taste Cards, and Wardrobe Simulation Memory all want the same compiler.

## Questions

- Can a Taste Constraint Card stay emotionally lightweight, or does it make taste feel over-formalized?
- Which constraints should expire automatically because taste changes with season/body/context?
- Can constraints be inferred from contradiction: things saved repeatedly but never used/worn/bought?
- Is the first wedge fashion, creator references, interiors, or brand-world fit?

## Failed searches / weak paths

- “AI stylist app” was too generic and product-shaped.
- Pure virtual try-on led back to existing crowded model demos.
- Creator-commerce analysis was promising but too dossier-like unless tied back to a primitive.

## Promoted signal

Taste should be compiled into executable constraints before downstream generation or recommendation.
