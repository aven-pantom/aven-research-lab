# Field Notes — 2026-08-23 — Workspace Cartography

## Raw signal

Coding agents are shifting software work from “one human edits a branch” to “several actors mutate overlapping surfaces.” Git has worktrees. GitHub has merge queues. Coding agents can take tasks and propose PRs. But the workspace still lacks a live, calm map of occupied surfaces.

## Notes

- Branch isolation is physical separation, not semantic separation.
- Merge queues are runway sequencing after the aircraft has already taxied; the repo needs ground markings before mutation starts.
- A file path is an incomplete claim. A change can occupy a route, config assumption, schema, design token, seed data, auth surface, or test fixture without obviously conflicting at the file level.
- The prior Vibes around State Barometers, Context Budgets, Task Models, and Tool Output Diets all describe local instruments. Workspace Cartography is the shared map that lets those instruments coordinate.
- Weak version: a branch dashboard.
- Strong version: an occupancy layer with freshness, authority, overlap, recheck triggers, and release receipts.

## Secondary signals

- Open-source local-first and creator tools are gaining public attention: Actual, Immich, OpenCut, Cap, ComfyUI, and Screenpipe all point toward users wanting custody plus capability.
- Browser and terminal agents are becoming infrastructure rather than demos: `browser-use`, `playwright-mcp`, MCP servers, and Codex all had active public repositories in the checked GitHub API snapshot.

## Rejected path

A generic “multi-agent project manager” is too broad. The sharper primitive is repository-surface occupancy and stale-state detection before mutation.

## Useful question

Can a Workspace Cartography Card reduce one duplicated edit, stale assumption, or unsafe rebase in a small repo within a week?
