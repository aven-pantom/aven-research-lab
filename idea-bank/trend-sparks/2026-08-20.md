# Trend Sparks — 2026-08-20

Exactly 10 current, evidence-backed app opportunities from visible product/social/technical movement. These are Trend Sparks, not generic ideas.

## Source scan

- **Agent safety/feed scan:** HN RSS surfaced agent-risk discussion including a WIRED rogue-agent story, a Register headline about an agent suggesting a malware package that could not be fully verified during this run, and `doover`, a small undo tool for Claude Code shell commands.
- **arXiv scan:** 2026 papers on GUI/computer-use agents, software-repair agents, and agentic workflow architecture show movement toward long-horizon, stateful, tool-using agents where persistent invalid state and auditability matter.
- **GitHub scan:** active high-star repositories around browser agents, desktop agents, Chrome DevTools MCP, DesktopCommanderMCP, AI video editors, local-first AI, and fashion/try-on prototypes show where builders are moving.
- **AI video/fashion scan:** arXiv results on native 2K virtual try-on, 3D garment generation, and canvas-native multimodal creative agents show creative/fashion tools are shifting from generation to controllable workflows.

## Selection logic

Chose sparks with visible behavior loops in Max's priority lanes: agent trust, local-first tools, creative tools, fashion/taste engines, creator funnels, civil-drone evidence, and weird consumer utilities. Preferred narrow artifacts that could be prototyped as cards, local apps, or tiny workbenches. Rejected generic AI wrappers, direct clones of dominant apps, “scanner” claims without evaluation, and monetization-only ideas.

## Anti-slop filter

Each Spark names the trend signal, existing proof, gap, smallest prototype, spread loop, risk, fit for Max, and evidence label. No fabricated users, revenue, download numbers, quotes, or unverified incident details are used. Claims from sources that were only partially accessible are marked weak/unknown.

## 1. Package Quarantine Card

- **Trend signal:** Computer-use agents, MCP tools, desktop agents, and coding agents increasingly install or request dependencies while performing delegated work.
- **Existing proof:** arXiv `UI-Mate`, `LegacyWorld`, `SCALECUA`, `Kozuchi Agent`; GitHub `doover`, `browser-use`, `UI-TARS-desktop`, `ChromeDevTools/chrome-devtools-mcp`, `DesktopCommanderMCP`; WIRED rogue-agent metadata.
- **Gap:** Dependency acquisition is treated as setup, not authority expansion with residue.
- **Smallest prototype:** Static local card generator for install-like commands: source, reason, install surface, authority gained, quarantine mode, rollback plan, residue receipt.
- **Why it could spread:** Agent power users already fear invisible environment changes; a card can be copied into PRs, logs, and approval flows.
- **Risk / why it may be fake:** Could become security theater without enforcement.
- **Fit for Max:** Direct Aven/Hermes, local-first agent, and trust-interface primitive.
- **Evidence label:** Verified / Supported / Inferred.

## 2. Do-Over Inbox for Agent Mistakes

- **Trend signal:** `doover` appeared as a small HN/GitHub signal for undoing Claude Code shell mistakes by snapshotting before destructive commands.
- **Existing proof:** GitHub metadata for `CaydenChik/doover`; existing lab Vibes on Undo Gravity, Transition Tests, Flight Recorders, and Shadow Runs.
- **Gap:** Undo tools exist as mechanics, but users need a calm inbox of what can be reversed, what cannot, and what residue remains.
- **Smallest prototype:** Local web viewer over a mock snapshot log: risky command, pre-state, affected files, restore button, irreversible residue note.
- **Why it could spread:** “Undo for agents” is immediately legible and demos well in developer social feeds.
- **Risk / why it may be fake:** Filesystem undo may not cover databases, credentials, network actions, or external services.
- **Fit for Max:** Strong agent-interface and local-first operations fit.
- **Evidence label:** Verified / Inferred.

## 3. Legacy Workflow Atomicity Tester

- **Trend signal:** `LegacyWorld` frames GUI-agent evaluation around atomicity in stateful legacy workflows where failed runs can leave invalid persistent changes.
- **Existing proof:** arXiv `LegacyWorld: Atomicity-Aware Evaluation of GUI Agents for Legacy Workflows`.
- **Gap:** Enterprises and small operators need pre-deployment dry runs that ask “what breaks if the agent stops halfway?” not just “did the demo finish?”
- **Smallest prototype:** Ten synthetic legacy-like browser forms with interruption points and Atomicity Cards: precondition, partial state, rollback, manual repair cost.
- **Why it could spread:** It turns vague agent reliability concerns into shareable failure fixtures.
- **Risk / why it may be fake:** Real legacy systems vary wildly; synthetic tasks may miss domain-specific hazards.
- **Fit for Max:** Strong Pantom/Orior operational tooling and agent-benchmark lane.
- **Evidence label:** Verified / Inferred.

## 4. Agent Install Surface Linter

- **Trend signal:** MCP and agent tools can touch terminals, filesystems, browsers, package managers, and devtools; users lack a fast way to see which surface an agent is about to mutate.
- **Existing proof:** GitHub metadata for DesktopCommanderMCP, Chrome DevTools MCP, browser-use, UI-TARS desktop; prior lab Capability Receipt and Credential Lease Vibes.
- **Gap:** Tool descriptions say what a tool does, but not whether it changes global machine state, project state, browser state, credential state, or external state.
- **Smallest prototype:** Paste a tool README / command / manifest and get a five-surface risk card plus missing-boundary checklist.
- **Why it could spread:** Easy social artifact: “this MCP server touches these surfaces.”
- **Risk / why it may be fake:** README parsing may be unreliable; maintainers may omit dangerous behavior.
- **Fit for Max:** Direct MCP, agent trust, and Hermes tooling fit.
- **Evidence label:** Supported / Inferred.

## 5. Canvas Agent Workbench for Creative Teams

- **Trend signal:** `JarvisHub` describes creative AI moving from single-step asset generation toward long-horizon multimodal production; GitHub AI video editor repos show active tool-building.
- **Existing proof:** arXiv `JarvisHub`; GitHub `OpenChatCut`, `Pallaidium`, `FableCut`, and other AI video editor scan results.
- **Gap:** Creative agents still return outputs in chat instead of manipulable canvas objects with sources, invariants, approvals, and diffs.
- **Smallest prototype:** Static canvas with three work objects: reference, generated variant, edit diff; each has receipt, protected invariant, and next action.
- **Why it could spread:** Designers already think spatially; workbench screenshots travel better than chat logs.
- **Risk / why it may be fake:** Could become another bloated whiteboard unless the object grammar is strict.
- **Fit for Max:** Strong creative-tool and interface-primitives lane.
- **Evidence label:** Verified / Supported / Inferred.

## 6. Fit Friction Try-On Ledger

- **Trend signal:** Recent arXiv fashion results target controllable 3D garment generation and high-resolution multi-garment virtual try-on.
- **Existing proof:** arXiv `Fashion-3DLR`, `WearWow`, `TAMF-VTON`; existing lab Vibes on Fit Ledgers, Negative Taste, Wardrobe Simulation Memory.
- **Gap:** Try-on tools render appearance, but rarely remember friction: tugging, confidence, context, return reason, almost-wear, and repeat discomfort.
- **Smallest prototype:** Local mobile/web ledger that stores outfit photo plus friction tags and converts repeated friction into style rules or resale candidates.
- **Why it could spread:** It turns the mirror moment into useful taste memory, not just a pretty render.
- **Risk / why it may be fake:** Manual logging may be too much work; virtual try-on quality may distract from memory.
- **Fit for Max:** Strong fashion/taste-engine and local-first personal software fit.
- **Evidence label:** Verified / Inferred.

## 7. Reference Contract Checker for AI Video

- **Trend signal:** AI video is moving toward controllable editing and reference-preserving workflows rather than one-shot generation.
- **Existing proof:** arXiv `PISCO`, `TeleStyle`, `JarvisHub`; GitHub AI video editor scan; existing lab Vibes on Reference Contracts, Reaction Cards, Intent Timelines.
- **Gap:** Creators can supply references, but tools rarely check whether protected identity/style/motion invariants survived an edit.
- **Smallest prototype:** Manual before/after checker that outputs a Reference Contract: protected properties, observed violations, allowed drift, next prompt.
- **Why it could spread:** Before/after creative critique is already social; invariant cards make it sharper.
- **Risk / why it may be fake:** Automated checking may be too weak; manual checking could slow flow.
- **Fit for Max:** Strong creative provenance and design-review lane.
- **Evidence label:** Verified / Supported / Inferred.

## 8. Local Creator Relationship Workshop

- **Trend signal:** GitHub scan shows local-first AI and single-user work tools gaining attention; creators continue operating across DMs, sponsors, editors, clients, and projects.
- **Existing proof:** GitHub scan for local-first AI/workspace repos; existing lab Single-File Workshop and Personal Software Workshop Vibes.
- **Gap:** Generic CRMs are too heavy; creators need a private relationship ledger with promised deliverables, context, follow-up, and receipts.
- **Smallest prototype:** Single-file local CRM with 50 contacts, last touch, next action, deal/context note, content/project link, export/restore.
- **Why it could spread:** It feels like a private operating desk rather than another platform.
- **Risk / why it may be fake:** Distribution is difficult; many creators tolerate messy DMs until pain is acute.
- **Fit for Max:** Pantom/Orior/creator-funnel adjacent.
- **Evidence label:** Supported / Inferred.

## 9. Drone Operation Side-Effect Card

- **Trend signal:** The lab's recent drone Vibes converged on weather, radio, acoustic, and public-intent evidence as route-local side effects.
- **Existing proof:** Existing Vibes: Weather Autopsies, Radio Weather, Acoustic Footprints, Airspace Manners; NASA/FAA noise and UAM sources from earlier 2026-08-20 run.
- **Gap:** Drone tools split operational evidence into separate maps/panels; public-facing artifacts need one side-effect card: air, radio, noise, privacy, expiry, uncertainty.
- **Smallest prototype:** 12 fictional simulator-only public cards for campus/warehouse/city routes with strict non-authorization language.
- **Why it could spread:** It is a better civic trust object than telemetry screenshots or legal notices.
- **Risk / why it may be fake:** Real operators may resist public uncertainty; legal review is required before field use.
- **Fit for Max:** Strong Notrex/N1 Scout and aviation-interface lane.
- **Evidence label:** Supported / Inferred.

## 10. Resident Agent Boundary Drill

- **Trend signal:** Local-first personal AI repos and mobile/desktop agent movement imply agents will increasingly live near notifications, files, meetings, browsers, and credentials.
- **Existing proof:** GitHub local-first AI scan; existing lab Vibes on Resident Microbrains, Attention Airlocks, Permission Receipts, Behavioral Canon, Credential Escrow.
- **Gap:** Users do not rehearse what a resident agent may ignore, summarize, wake, ask, or refuse before it is installed.
- **Smallest prototype:** 50-event drill deck where a user classifies events into ignore/local-handle/wake/human/forbidden and exports a Boundary Canon.
- **Why it could spread:** It makes personal AI setup feel like training a house rule system, not configuring settings.
- **Risk / why it may be fake:** Without OS integration, it may remain a toy; users may not want upfront drills.
- **Fit for Max:** Strong Aven/Hermes continuity and local-first personal-agent fit.
- **Evidence label:** Supported / Inferred.

2. **Do-Over Inbox for Agent Mistakes** — simple social demo and direct user pain.
3. **Fit Friction Try-On Ledger** — best consumer/fashion lane because it captures taste memory, not just generated images.
