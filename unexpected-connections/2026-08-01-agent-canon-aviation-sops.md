# Unexpected Connection — Agent Canon and Aviation SOPs

## Connection

Personal AI behavioral canon and aviation standard operating procedures solve the same hidden problem: remembering information is not enough when repeated action carries risk, judgment, and context.

## Shared structure

A pilot can know an aircraft well and still needs checklists, callouts, emergency procedures, minima, handoff rituals, and change logs. The point is not that pilots have bad memory. The point is that important behavior must live outside the actor as inspectable doctrine.

Personal agents are entering the same regime. Once an agent can run background tasks, touch files, schedule work, use credentials, message people, or operate connected devices, “it remembers me” is insufficient. It needs a local operating doctrine that says:

- what requires approval,
- what should be retried,
- what should be abandoned,
- what counts as irreversible,
- when to interrupt,
- how to communicate uncertainty,
- which standards are taste rather than fact,
- which old rules have expired.

## Transferable mechanism

Aviation suggests the canon should not be a blob of preferences. It should be procedural, versioned, scoped, rehearsed, and updated after incidents. Agent mistakes should produce doctrine patches the way safety incidents produce checklist or SOP changes.

## Why this matters

The highest-value personal agent may not be the one with the most memories. It may be the one with the clearest doctrine, best review ritual, and most graceful way to distinguish fact memory from behavioral law.
