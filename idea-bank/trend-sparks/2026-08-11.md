# Trend Sparks — 2026-08-11

## Date
2026-08-11

## Source scan
Checked near-primary and direct-source signals: MCP authorization spec, OAuth 2.1 draft, GNAP/RFC 9635, FedCM, WebAuthn, Vault leases, AWS temporary credentials, GitHub fine-grained PAT documentation, prior lab agent-interface Vibes, and current ecosystem behavior around terminal/browser agents, MCP servers, AI video, local-first utilities, fashion/taste engines, creator workflows, and drone/aviation interfaces. arXiv API searches for agent credential management returned timeouts/429s, so no arXiv paper is cited in this run.

## Selection logic
Selected Sparks where a visible behavior loop is becoming common but the product primitive is still missing: delegated authority, agent receipts, handoffs, local custody, controllable AI media, taste capture, and route-level aviation context. I prioritized opportunities Max could prototype as calm, local-first, interface-forward tools without needing platform permission first.

## Anti-slop filter
Rejected: generic AI wrappers, “ChatGPT for X,” cloned social feeds, password-manager reskins without task authority, video-generation prompt boxes without review mechanics, vague fashion AI stylists, drone safety claims requiring operational validation, and monetization-only creator funnels.

## 10 Trend Sparks

### 1. Credential Lease Wallet

- **Trend signal:** Agents increasingly need OAuth tokens, API keys, browser sessions, PATs, and MCP authorization, but users cannot see task-scoped authority.
- **Existing proof:** **Verified:** MCP authorization, OAuth 2.1, GNAP/RFC 9635, Vault leases, AWS temporary credentials, and GitHub fine-grained PATs all exist as direct source material.
- **Gap:** No consumer/builder-facing wallet where each agent credential is a task lease with expiry, allowed actions, forbidden actions, revocation, and receipts.
- **Smallest prototype:** Static local lease-card wallet with 10 mock credentials and states: active, stale, needs approval, expired, revoked.
- **Why it could spread:** “What did I let this agent touch?” is becoming a universal anxiety for agent users.
- **Risk / why it may be fake:** Platform vendors may absorb the flow; users may ignore permission cards unless the design is radically compact.
- **Fit for Max:** Very strong: agent trust, local-first custody, interface design, and Aven/Hermes operations.
- **Evidence label:** Supported

### 2. Agent Revocation Inbox

- **Trend signal:** Agent tasks create lingering authorizations across repos, SaaS apps, browsers, and local tools.
- **Existing proof:** **Verified:** GitHub supports fine-grained tokens; cloud/IAM systems support temporary credentials; Vault supports revocation.
- **Gap:** Revocation is scattered across dashboards and docs, not surfaced as an inbox of “authority still alive.”
- **Smallest prototype:** Local checklist that imports mock lease cards and groups live permissions by urgency, expiry, scope, and revoke action.
- **Why it could spread:** It turns invisible risk into a satisfying cleanup ritual.
- **Risk / why it may be fake:** Without integrations, it may be only a pretty checklist; with integrations, security complexity rises quickly.
- **Fit for Max:** Strong fit with Permission Receipts, Capability Manifests, and operational dashboards.
- **Evidence label:** Inferred

### 3. Browser Session Sublease

- **Trend signal:** Browser agents operate inside logged-in sessions where the real credential is often a cookie/session, not an API token.
- **Existing proof:** **Verified:** FedCM and WebAuthn show browser-level identity primitives; prior lab work captured browser-agent receipts and shadow runs.
- **Gap:** Users cannot say “this agent may use my logged-in session for only these three actions for ten minutes.”
- **Smallest prototype:** Mock browser-agent task page with a sublease panel: allowed selectors/routes, forbidden submissions, expiry timer, and receipt.
- **Why it could spread:** The demo is immediately legible: safer agent browsing without giving away the whole account.
- **Risk / why it may be fake:** Real browser enforcement may require extension or browser-vendor support.
- **Fit for Max:** Strong fit with browser agents, shadow runs, and interface primitives.
- **Evidence label:** Inferred

### 4. MCP Install Risk Card

- **Trend signal:** MCP servers are spreading as installable agent capabilities.
- **Existing proof:** **Verified:** MCP has official docs/specs including authorization; prior lab work tracked Capability Receipt Manifests.
- **Gap:** Installing a server still feels like reading a README and hoping permissions are sane.
- **Smallest prototype:** Five-card bench for MCP servers: requested secrets, network/file access, reversible actions, sample receipt, failure mode.
- **Why it could spread:** Developers want quick “should I trust this capability?” artifacts.
- **Risk / why it may be fake:** Could become a directory unless paired with real local traces.
- **Fit for Max:** Very strong: Pantom/Orior-style dossiers plus agent tool infrastructure.
- **Evidence label:** Supported

### 5. Creator Asset Custody Card

- **Trend signal:** AI-assisted creators move references, prompts, clips, exports, and client feedback across many tools.
- **Existing proof:** **Supported:** Prior lab Vibes on provenance sandboxes, reference contracts, intent timelines, and reaction cards all converge on creator-owned process memory.
- **Gap:** Existing project folders know file paths, not custody: source, rights note, edit role, approval status, and export consequence.
- **Smallest prototype:** Drag a folder into a local page; generate one custody card per asset with role, allowed use, forbidden mutation, and output link.
- **Why it could spread:** Process breakdowns and “asset maps” are shareable and useful for client trust.
- **Risk / why it may be fake:** Creators may not add metadata unless capture is nearly automatic.
- **Fit for Max:** Strong fit with Orior/Pantom visual systems and creator tooling.
- **Evidence label:** Inferred

### 6. AI Video Invariant Checker

- **Trend signal:** AI video is moving from generation novelty toward repeatable edit control.
- **Existing proof:** **Supported:** Existing lab sources already identified Intent Timelines, Reaction Cards, and Reference Contracts as related control primitives.
- **Gap:** Creators lack a small review surface for “what must not change” between variants.
- **Smallest prototype:** Upload before/after frames or screenshots; mark protected properties; output preserved/broken/unknown review card.
- **Why it could spread:** Before/after invariant checks make failures visually obvious and social-post friendly.
- **Risk / why it may be fake:** Model-native tools may improve enough to own this internally.
- **Fit for Max:** Strong fit with creative tools and taste-led UI.
- **Evidence label:** Supported

### 7. Almost-Wear Capture

- **Trend signal:** Outfit apps tend to log successful looks, but the stronger taste signal is what was rejected at the mirror.
- **Existing proof:** **Supported:** Prior lab work on negative taste events and wardrobe simulation memory identifies skips, returns, and almost-wears as high-signal taste data.
- **Gap:** No low-friction diary for “almost wore it, didn’t, why.”
- **Smallest prototype:** One-tap camera/notes flow with reason chips: fit, weather, confidence, event mismatch, color, silhouette, too loud, too safe.
- **Why it could spread:** The entries are funny, intimate, and useful; rejection is more memetic than polished outfit logging.
- **Risk / why it may be fake:** Capture friction may kill daily use.
- **Fit for Max:** Strong fit with fashion/style/taste engines.
- **Evidence label:** Inferred

### 8. Local Decision Room

- **Trend signal:** Local-first apps and personal AI both point toward private workspaces before cloud commitment.
- **Existing proof:** **Supported:** Prior lab Vibes on browser workshops, personal software workshops, tiny worlds, and local agent custody converge here.
- **Gap:** People use chats for decisions, but chats do not preserve alternatives, evidence, criteria, and final choice as a manipulable local artifact.
- **Smallest prototype:** Single-file decision room: options, evidence cards, tradeoffs, red-team notes, final decision, exportable memo.
- **Why it could spread:** Decision artifacts are easy to share after the fact, and private deliberation has obvious value.
- **Risk / why it may be fake:** Could become a generic notes app unless it has a strong decision grammar.
- **Fit for Max:** Very strong: local-first, calm interface, builder/operator use.
- **Evidence label:** Inferred

### 9. Drone Route Receipt Simulator

- **Trend signal:** Civil drone autonomy research keeps needing public trust, local weather, route context, and non-operational explanation surfaces.
- **Existing proof:** **Supported:** Prior lab Vibes on Airspace Manners, Low-Altitude Weather, and Drone Module Contracts establish the source base.
- **Gap:** Drone route planning is either operational/safety-critical or too generic; there is room for simulator-only educational route receipts.
- **Smallest prototype:** Fictional route card showing intent, air-street conditions, uncertainty, no-fly constraints, and why the simulated flight was accepted/rejected.
- **Why it could spread:** Screenshots teach the public what good drone behavior should disclose.
- **Risk / why it may be fake:** Must avoid implying real-world operational safety; regulation and data quality are hard.
- **Fit for Max:** Strong fit with N1 Scout/Notrex-adjacent aviation interface work.
- **Evidence label:** Supported

### 10. Agent Work Expiry Timer

- **Trend signal:** Long-running agents, background jobs, and continuation ports create stale context and dangling decisions.
- **Existing proof:** **Supported:** Prior lab Vibes on Peripheral Vision, Continuation Ports, Shadow Runs, and Undo Gravity converge on staleness and recoverability.
- **Gap:** Agent UIs rarely show when a plan, credential, observation, or permission is no longer safe to use.
- **Smallest prototype:** Menubar/local web timer that tracks task phase, last verified state, expiring assumptions, expiring credentials, and required recheck.
- **Why it could spread:** “Your agent’s confidence is expired” is a sharp, demonstrable interface moment.
- **Risk / why it may be fake:** Users may find timers annoying unless they prevent real mistakes.
- **Fit for Max:** Very strong: Aven/Hermes operations, agent peripheral vision, continuation ports.
- **Evidence label:** Supported

## Strongest three to watch
1. **Credential Lease Wallet** — sharpest convergence of standards, agent trust, and visible interface primitive.
2. **Browser Session Sublease** — hardest technically, but most emotionally legible to users.
3. **Agent Work Expiry Timer** — smallest prototype with immediate usefulness across current Aven/Hermes workflows.
