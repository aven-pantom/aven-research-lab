## Selection logic
The 10 selected Sparks are current because they attach to visible infrastructure and behavior: terminal agents, browser agents, MCP/tool ecosystems, local-first apps, browser ML, creator video tooling, virtual outfit tools, and the growing habit of using agents for real work. I excluded generic “AI wrapper” products, direct copies of ChatGPT/Copilot, and monetization-only funnels without a behavior loop.

## 10 Trend Sparks

### 1. Continuation Port Viewer

- **Trend signal:** Terminal agents, browser agents, Apps SDK components, and MCP servers are all active surfaces, but work still gets handed off as prose.
- **Existing proof:** **Verified:** GitHub API checks showed active high-attention repos for Claude Code, Gemini CLI, Stagehand, MCP servers, and OpenAI CUA sample app on 2026-08-11.
- **Gap:** No small user-owned object for resuming agent work across surfaces with permissions, stale-state warnings, and verification gates.
- **Smallest prototype:** Static Markdown/JSON viewer that imports a task handoff card and shows last verified state, risks, allowed next actions, forbidden actions, and raw trace links.
- **Why it could spread:** Every agent user eventually loses time re-explaining context; a shareable “resume this task” card is easy to demonstrate.
- **Risk / why it may be fake:** Platforms may keep task state proprietary; users may tolerate messy summaries if model performance keeps improving.
- **Fit for Max:** Directly aligned with Aven/Hermes continuity, local-first agent tools, and tastefully designed operational interfaces.
- **Evidence label:** Supported

### 2. Agent Handoff Inbox

- **Trend signal:** People increasingly run multiple coding/assistant agents in parallel, creating unfinished threads, PRs, browser sessions, and local files.
- **Existing proof:** **Verified:** Claude Code and Gemini CLI both show very large active GitHub attention; HN search surfaced recent vibe-coding and agent-client discussions.
- **Gap:** No calm inbox for “agent work waiting for human decision” across tools.
- **Smallest prototype:** Local folder watcher that turns agent-generated Markdown handoffs into cards: approve, reject, resume, archive, or request shadow run.
- **Why it could spread:** Screenshots of chaotic agent work becoming a clean command center would be legible to builders.
- **Risk / why it may be fake:** Heavy users may already manage this with Git branches, issues, and chats; casual users may not run enough agents to need it.
- **Fit for Max:** Strong fit with agent peripheral vision, shared workbenches, and Aven as operator.
- **Evidence label:** Inferred

### 3. Browser Agent Receipt Wallet

- **Trend signal:** Browser-agent SDKs and computer-use agents are becoming developer primitives.
- **Existing proof:** **Verified:** Browserbase Stagehand is an active browser-agent SDK; OpenAI computer-use docs and sample app provide near-primary evidence for CUA workflows.
- **Gap:** Browser agents can act on live pages, but users lack portable receipts of what was seen, clicked, submitted, skipped, or blocked.
- **Smallest prototype:** Chrome/local web viewer that stores one receipt per browser-agent task with DOM snapshot pointer, action list, side-effect classification, and undo notes.
- **Why it could spread:** Trust screenshots and “what did my agent do?” posts are highly shareable when the receipt is visual.
- **Risk / why it may be fake:** Browser automation platforms may build receipts internally; privacy/legal complexity may slow adoption.
- **Fit for Max:** Strong fit with flight recorders, transition tests, and agent trust interfaces.
- **Evidence label:** Supported

### 4. MCP Capability Bench

- **Trend signal:** MCP servers are proliferating quickly, but discovery quality is likely uneven.
- **Existing proof:** **Verified:** `modelcontextprotocol/servers` showed 89,421 stars and same-day activity in the GitHub API check.
- **Gap:** Users can see that a server exists, but not what it can safely do, what permissions it needs, what it returns, or whether it produces good receipts.
- **Smallest prototype:** Five-card comparison bench for popular MCP servers: capabilities, permissions, sample task, failure mode, and receipt quality.
- **Why it could spread:** “MCP server safety/taste cards” give developers a fast way to compare tools without reading every README.
- **Risk / why it may be fake:** Could collapse into a generic directory unless the cards are opinionated and tested.
- **Fit for Max:** Strong fit with tool manifests, capability receipts, and productized research dossiers.
- **Evidence label:** Supported

### 5. Local Model Duty Router

- **Trend signal:** Browser/local ML and resident microbrain patterns are becoming more practical.
- **Existing proof:** **Verified:** Transformers.js is active and positions itself as running models directly in the browser without a server; prior lab work captured resident microbrains.
- **Gap:** Users need a tiny routing layer that decides which events are handled locally, escalated to cloud, ignored, or held for human review.
- **Smallest prototype:** Local-only event classifier demo with five duty cards and 50 mock events.
- **Why it could spread:** It makes privacy and latency visible instead of abstract.
- **Risk / why it may be fake:** On-device models may still be too weak for ambiguous tasks; OS-level vendors may absorb the primitive.
- **Fit for Max:** Very strong fit with local-first agents, mobile permission receipts, and Aven’s operating doctrine.
- **Evidence label:** Supported

### 6. Outfit Rejection Diary

- **Trend signal:** Fashion/outfit AI tools keep appearing, but most focus on positive try-on or “style me” outputs.
- **Existing proof:** **Verified:** HN search surfaced LookTake as an outfit/makeup/hairstyle try-on product; prior lab research identified negative taste as a stronger primitive than generic try-on.
- **Gap:** Apps rarely capture why something almost worked but was rejected.
- **Smallest prototype:** Camera roll/notes flow where users log rejected outfits with reason chips, weather/context, and “what would fix it.”
- **Why it could spread:** Rejection logs are funny, personal, and more social than polished outfit boards.
- **Risk / why it may be fake:** Users may not want friction before getting dressed; needs a fast capture mechanic.
- **Fit for Max:** Strong fit with fashion taste engines and negative-space taste work.
- **Evidence label:** Inferred

### 7. AI Video Variant Judge

- **Trend signal:** AI video editing and generation conversations keep shifting from making clips to controlling revisions.
- **Existing proof:** **Verified:** HN search surfaced an AI color grader and recent AI video/editing-adjacent Show HN items; prior lab work captured Reaction Cards and Intent Timelines.
- **Gap:** Creators need a way to judge whether a variant preserved the intended invariant, not just whether it looks good.
- **Smallest prototype:** Upload two short clips or mock frames; fill a Reference/Reaction Card; compare changed, preserved, broken, and unknown elements.
- **Why it could spread:** Before/after variant cards are inherently shareable and useful in creator workflows.
- **Risk / why it may be fake:** If model-native edit controls become excellent, external judging tools may be temporary.
- **Fit for Max:** Strong fit with creative tools, Pantom/Orior visual systems, and reference contracts.
- **Evidence label:** Supported

### 8. Local-First Money Room

- **Trend signal:** Local-first software remains visible, including personal finance and accounting replacements.
- **Existing proof:** **Verified:** Actual Budget showed 28,077 stars and same-day GitHub activity; HN search surfaced a local-first accounting replacement.
- **Gap:** Personal finance apps are often either heavy ledgers or bank-sync dashboards; they rarely feel like a calm planning room for one decision.
- **Smallest prototype:** Single-file budget scenario room: import/export JSON, three scenarios, one decision memo, no bank credentials.
- **Why it could spread:** Private money decisions are stressful; a beautiful local room with no account linking is differentiated.
- **Risk / why it may be fake:** Finance behavior is sticky and trust-heavy; without sync, retention may be limited.
- **Fit for Max:** Medium-high fit: local-first, design-heavy, weird consumer utility.
- **Evidence label:** Supported

### 9. Creator Clip Source Locker

- **Trend signal:** Creator tools are becoming agent-assisted, but source assets, references, prompts, and final variants scatter across apps.
- **Existing proof:** **Verified:** Vercel AI SDK and OpenAI Apps SDK indicate AI app surfaces are easy to build; prior lab work captured provenance sandboxes and reference contracts.
- **Gap:** No tiny locker that keeps a clip’s references, prompts, exports, rights notes, and variant decisions together.
- **Smallest prototype:** Drag-and-drop local folder that generates one Source Locker card for a short video project.
- **Why it could spread:** Creators already share process breakdowns; source lockers turn process into a reusable artifact.
- **Risk / why it may be fake:** Existing editors may add asset/project provenance; standalone locker must be very lightweight.
- **Fit for Max:** Strong fit with creator funnels, Orior dossiers, and AI media provenance.
- **Evidence label:** Inferred

### 10. Street-Level Drone Weather Card

- **Trend signal:** Civil drone/AAM interfaces need operational context below airport-scale forecasts.
- **Existing proof:** **Supported:** Prior lab research captured low-altitude weather and airspace-manners as active Vibes; broader drone operations depend on localized weather and route risk.
- **Gap:** Consumer/prosumer drone users do not get a simple route-specific “air street” condition card.
- **Smallest prototype:** Simulator-only fictional route card combining wind band, turbulence risk, visibility, obstacles, and no-fly warnings with clear non-operational disclaimers.
- **Why it could spread:** Drone creators and aviation people understand route cards visually; screenshots would communicate the need quickly.
- **Risk / why it may be fake:** Real operational use is regulated and safety-sensitive; must stay simulator/education-first until source quality is much stronger.
- **Fit for Max:** Strong fit with N1 Scout, drones, aviation interfaces, and tasteful safety UX.
- **Evidence label:** Inferred
