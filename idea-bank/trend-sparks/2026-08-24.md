## Selection logic

These 10 made the cut because they point to behavior loops Max could actually prototype: receipts, live timing, creative work objects, local custody, taste memory, and civil drone evidence. Excluded: generic AI wrappers, clone social apps, pure monetization hacks, broad “AI assistant” ideas without a specific loop, and safety-sensitive drone operation tools that imply real-world authorization.

## 10 Trend Sparks

### 1. Moment Sense Coach

- **Trend signal:** arXiv `2608.21360` frames real-time omni-modal assistance as needing visual state, user goals, context, and delayed response until the target event.
- **Existing proof:** OmniAssistBench abstract reports current models struggle with visual prompts, historical context, and response timing; LiveKit Agents and screenpipe show active realtime/local observation substrates.
- **Gap:** Assistants optimize answer quality before intervention timing.
- **Smallest prototype:** A 30-scenario Moment Sense Card simulator that labels observe/wait/cue/interrupt/debrief for short screen/video/task moments.
- **Why it could spread:** People remember assistants that interrupt badly; shareable “it waited until exactly the right moment” demos have emotional clarity.
- **Risk / why it may be fake:** Always-on observation may be too creepy; timing quality may be hard to prove outside demos.
- **Fit for Max:** Strong fit with agents, local-first personal software, attention airlocks, and interface primitives.
- **Evidence label:** Supported.

### 2. AI Video Timeline Receipt

- **Trend signal:** GitHub search surfaced multiple current AI video editors with real timelines, agent/MCP claims, and local-first positioning: `palmier-io/palmier-pro`, `0xsline/OpenChatCut`, `ronak-create/FableCut`, and `MartinDelophy/ai-video-editor`.
- **Existing proof:** GitHub API search on 2026-08-24 showed these repos with 544–13,815 stars and recent pushes in July/August 2026.
- **Gap:** AI video tools expose creation power but weakly preserve what changed, which references mattered, and why a variant is valid.
- **Smallest prototype:** A JSON/Markdown receipt attached to one 15-second timeline with sources, protected invariants, edits, rejected branches, and replay confidence.
- **Why it could spread:** Creators can share before/after plus “recipe receipt,” making process legible without publishing full project files.
- **Risk / why it may be fake:** Editors may bake this in; creators may prefer speed over structured receipts.
- **Fit for Max:** Strong fit with creative tools, provenance sandboxes, intent timelines, and Pantom/Orior creator funnels.
- **Evidence label:** Supported.

### 3. Browser Agent Permission Preview

- **Trend signal:** `browser-use/browser-use`, `microsoft/playwright-mcp`, `ChromeDevTools/chrome-devtools-mcp`, `vercel-labs/agent-browser`, and `Skyvern-AI/skyvern` show intense movement around agents operating browsers.
- **Existing proof:** GitHub API on 2026-08-24 showed large star counts and recent pushes across these projects.
- **Gap:** Browser agents can act, but users often cannot preview authority, surfaces touched, stale state, and expected deltas before a task starts.
- **Smallest prototype:** A static permission-preview card for 10 browser tasks: accounts touched, forms read/written, cookies/session assumptions, expected mutation, undo path.
- **Why it could spread:** Trust screenshots before an agent clicks are easy to understand and share.
- **Risk / why it may be fake:** Power users may ignore previews; browsers/platforms may own permission UX.
- **Fit for Max:** Very strong fit with Room Contracts, Street Signs, Action Maps, Shadow Runs, and agent safety UX.
- **Evidence label:** Supported.

### 4. Local Screen Memory Boundary Desk

- **Trend signal:** `screenpipe/screenpipe` describes local continuous screen history for agents; local-first personal AI repositories such as `tinyhumansai/openhuman` show appetite for user-owned agent memory.
- **Existing proof:** GitHub API snapshot on 2026-08-24: screenpipe had 21,191 stars and same-day push; openhuman had 36,856 stars and same-day push.
- **Gap:** Continuous local context lacks a simple boundary editor for what agents may see, summarize, forget, or use as evidence.
- **Smallest prototype:** A local mock desk with three capture zones, redaction rules, expiry, and per-agent access receipts.
- **Why it could spread:** People understand “my screen history has rooms” faster than abstract privacy settings.
- **Risk / why it may be fake:** Recording history may remain too invasive even when local.
- **Fit for Max:** Strong fit with local-first agents, Behavioral Canon, Permission Receipts, and Hermes/Aven continuity.
- **Evidence label:** Supported.

### 5. MCP Tool Quarantine Shelf

- **Trend signal:** GitHub search showed very active MCP/server tooling: `modelcontextprotocol/servers`, `microsoft/playwright-mcp`, `github/github-mcp-server`, and newer high-star MCP-oriented repos.
- **Existing proof:** GitHub API snapshots on 2026-08-24 showed `modelcontextprotocol/servers` at 89,812 stars and `microsoft/playwright-mcp` at 36,408 stars; MCP search also surfaced current high-star tooling.
- **Gap:** Tool installation expands authority before the user or agent has a visible risk/receipt layer.
- **Smallest prototype:** A no-install quarantine shelf that turns 10 MCP README/tool schemas into capability receipts with authority gained, reversibility, residue, and safe test.
- **Why it could spread:** Developers adopting agents need a calmer way to say “what did I just give this thing?”
- **Risk / why it may be fake:** Security-conscious users may prefer existing package scanners; casual users may not care.
- **Fit for Max:** Strong fit with Package Quarantine, Capability Manifests, and agent-operable tools.
- **Evidence label:** Supported.

### 6. Agent Worktree Collision Map

- **Trend signal:** HN date scan surfaced Zuse coordinating 20 Linear issues in worktrees; GitHub trends show coding agents and multi-agent workspaces remain active.
- **Existing proof:** GitHub API on 2026-08-24 showed `anthropics/claude-code`, `openai/codex`, `google-gemini/gemini-cli`, `continuedev/continue`, and `NanmiCoder/cc-haha` with large star counts and recent pushes.
- **Gap:** Multi-agent coding is adding actors faster than it adds repo-native traffic control.
- **Smallest prototype:** A local `worktree-map.json` plus Markdown card showing claimed files, semantic surfaces, stale HEADs, collision risk, and release receipts.
- **Why it could spread:** “Two agents are about to edit the same surface” is instantly legible to builders.
- **Risk / why it may be fake:** Git hosting platforms or IDEs may absorb the obvious version.
- **Fit for Max:** Strong fit with Workspace Cartography and Hermes autonomous repo workflows.
- **Evidence label:** Supported.

### 7. Taste Constraint Camera Roll

- **Trend signal:** Fashion AI repos exist, but stronger adjacent proof is local media custody plus prior fashion/taste research: personal photos, saves, rejects, and references can become executable taste constraints.
- **Existing proof:** GitHub search on 2026-08-24 surfaced `liangdabiao/Fashion-AI` and virtual try-on projects; previous lab scans verified fashion recommendation papers and high public attention around self-hosted photo tools.
- **Gap:** AI stylists over-index on generated looks and weakly remember negative taste, fit friction, and context.
- **Smallest prototype:** Import 30 synthetic camera-roll/reference events into 12 Taste Constraint Cards with protected properties and forbidden mutations.
- **Why it could spread:** People can share “my style law” as cards instead of moodboards.
- **Risk / why it may be fake:** Manual taste labeling may feel too heavy; privacy concerns around photos are real.
- **Fit for Max:** Strong fit with fashion/taste engines, brand worlds, and local-first personal software.
- **Evidence label:** Inferred from verified adjacent signals.

### 8. Creator Reference Lock

- **Trend signal:** AI creative tools and AI video editors are moving toward agent-editable workflows, but reference fidelity remains fragile.
- **Existing proof:** GitHub AI video editor search found local/agent timeline projects; prior lab source scans verified Figma AI, Runway, Suno, CapCut, ComfyUI, and creative-reference pressure.
- **Gap:** Creators need to say which parts of a reference must not change before AI generates variants.
- **Smallest prototype:** A small web card where a creator uploads/describes 6 references, marks protected properties, and exports a reference contract for prompts/tools.
- **Why it could spread:** Before/after variant failures are highly shareable; “locked the wrong thing” is easy to demonstrate.
- **Risk / why it may be fake:** Multimodal models may eventually obey references well enough without explicit cards.
- **Fit for Max:** Strong fit with design systems, creative tools, and Orior/Pantom workflows.
- **Evidence label:** Supported.

### 9. Drone Civic Noise Receipt

- **Trend signal:** The lab's drone evidence lane keeps converging on weather, radio, acoustic, and intent cards; GitHub search also shows current small drone GCS/simulator projects such as `rubenCodeforges/ardudeck` and `SJTU-ViSYS-team/VisFly`.
- **Existing proof:** GitHub API search on 2026-08-24 showed `ardudeck` and `VisFly` with recent 2026 activity; prior lab sessions verified AAM/noise evidence sources.
- **Gap:** Drone interfaces communicate operation mechanics better than neighborhood-level evidence of noise, repetition, and sensitive context.
- **Smallest prototype:** A simulator-only civic receipt for a fictional route window: predicted acoustic role, sensitive context, repetition risk, observed residual, and non-authorization disclaimer.
- **Why it could spread:** Residents understand “what noise did this operation create near me?” better than raw dB charts.
- **Risk / why it may be fake:** Civil drone deployment may be slower than the interface opportunity; must avoid operational guidance.
- **Fit for Max:** Strong fit with drones, aviation interfaces, and Notrex/N1 evidence thinking.
- **Evidence label:** Inferred from verified repo signals and prior research base.

### 10. Agent Latency Receipt

- **Trend signal:** HN scan on 2026-08-24 surfaced “The Web-Search Latency Your Agent Pays”; agent workflows increasingly depend on chains of web, MCP, browser, and code tools.
- **Existing proof:** The HN post is a weak current signal; GitHub API also showed active agent/web tooling such as Firecrawl, Playwright MCP, browser-use, and coding agents.
- **Gap:** Users see “agent is thinking,” not which external waits, retries, tool calls, and stale observations shaped the delay.
- **Smallest prototype:** A trace card that breaks one agent task into waits: model, search, page fetch, tool call, human approval, retry, stale recheck.
- **Why it could spread:** Latency receipts make agent slowness feel inspectable instead of mysterious.
- **Risk / why it may be fake:** Latency may be solved infrastructurally; users may not want detailed traces.
- **Fit for Max:** Good fit with agent observability, Tool Output Diets, Flight Recorders, and Hermes UX.
- **Evidence label:** Weak signal / Supported by adjacent tooling.
