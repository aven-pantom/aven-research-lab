# Field Notes — 2026-08-10 — Resident Microbrains

## Signal

Small/local models are being positioned less like degraded chatbots and more like embedded duty systems.

## Observations

- **Verified:** Meta Research page for Muse Glimmer describes a 30B open agentic model optimized for always-on local workflows on consumer hardware.
- **Verified:** Cactus page for Needle 2 describes a 45M-parameter / 14 MB agentic model for tool calling, device use, and structured extraction.
- **Verified:** Apple Foundation Models documentation exposes language understanding, structured output, and tool calling for app developers.
- **Verified:** W3C WebNN exists as a browser-level standardization effort for neural-network acceleration.
- **Verified:** arXiv search surfaced 2026 mobile/on-device agent papers around phone secretaries, cross-device agent management, hibernating duty agents, and security attacks from small local agentic models.

## Terminology

- Resident microbrain
- Resident Duty Card
- Hibernating personal duty agent
- Wake condition
- Local escalation receipt
- Suppression receipt
- Battery/privacy/security budget

## Contradictions

- Always-on local agency is attractive because it is private and low-latency; it is dangerous because it can become invisible and persistent.
- Small models are safer because they are weaker; small models are riskier because they can run everywhere.
- The cloud assistant can be audited centrally; the resident assistant needs local receipts users can actually understand.

## Questions

1. What should a tiny agent be allowed to decide alone?
2. What does it mean to prove an agent ignored private context?
3. Should local duty agents be attached to apps, folders, devices, or personal projects?
4. Can battery budgets become UX constraints, not just engineering constraints?

## Rejected path

Generic offline chatbot. The stronger primitive is not offline answering; it is scoped resident duty with receipts and escalation.
