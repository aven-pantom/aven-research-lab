# Rejected Path — Generic MCP Marketplace

## Why it initially seemed promising

MCP registries, Docker’s MCP catalog, OpenAI Apps SDK packaging, Product Hunt “Skill” language, and HN maker signals all point toward tool distribution for agents. The obvious product is a marketplace for MCP servers.

## What evidence weakened it

- **Verified:** The MCP Registry already describes itself as “like an app store for MCP servers.”
- **Verified:** Docker already runs an official MCP registry/catalog with security and curation language.
- **Verified:** Community lists such as `punkpeye/awesome-mcp-servers` already have high attention.
- **Supported:** A generic marketplace competes on inventory and SEO, not on the deeper trust primitive.

## Which assumption failed

The weak assumption was that discovery is the main missing piece. The stronger problem is permissioned use: what the tool may do, what it has proven, how it behaves in a local runtime, and what evidence it leaves after delegated action.

## Whether it may become viable later

A marketplace could become viable as a surface over a better trust ledger, but not as the primary invention.

## Useful remnants

- Tool categories and search matter.
- Screenshots/UI examples matter for non-developer users.
- Ratings may matter, but should be subordinate to receipts, traces, revocation, and permission envelopes.

## Future signal that should trigger reconsideration

Reconsider if users begin installing MCP tools directly from consumer agent surfaces and complain about discovery, comparison, pricing, or “which tool do I trust for this task?” rather than developer setup.
